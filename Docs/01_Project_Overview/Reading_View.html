1A 魔法朋克呈现建议

场地以金属结构、管线、符文和晶核驱动的机械工坊呈现。主武器表现为魔导步枪，敌人可采用魔导构装体，死亡后留下带封印的机关核心。D01 用符文活塞/地脉柱表达弹射，D02 用晶核封印破裂表达爆炸，D03 用咒印发射器表达定向火线；这是表现层映射，沿用同一套触发与伤害规则。

蛾翼轮廓、灯光与逐级亮起的符文可呼应名称与连锁主题。它们只作为图标、材质和反馈提案，不增加蛾群 AI、飞行角色或召唤机制。具体资源规格见 关卡、界面与资源规格。

2 核心体验

一句话介绍：在会不断留下机关的战场中，击败敌人，搬运机关，用一枪启动自己布置的连锁攻击。

玩家主要做四种判断：在哪里击败敌人，留下的机关能影响谁，投掷到什么位置，以及在什么时候开枪启动。直接射击提供基本生存能力；机关提供对位置、方向与时机的利用空间。

主题表达来自同一套规则的组合。例如柱子可以抬起炸弹，发射器的弹丸可以击中这枚炸弹，爆炸又可以推开另一台正在发射的装置。结果应来自实际位置、运动与命中，而不是某个预写的组合技能。

判定设计成立的观察项：玩家能够主动重复一条连锁；换一个位置会产生不同结果；玩家能解释成功或失败的原因。华丽特效本身不作为机制成立的证据。

3 核心循环

击败敌人 → 观察其掉落 → 拾取或直接利用 → 投掷到攻击位置 → 射击启动 → 连锁改变战场 → 完成当前波次。

场内原地掉落使击杀位置有意义。三类敌人变体采用固定掉落，帮助玩家提前规划。P0 不采用随机掉落；敌人的外观、死亡后的道具外形与图标保持对应。

4 玩家与基础战斗

采用官方 Third Person 模板人物和基础移动动画作为起点，加入越肩相机、一把步枪、血量和跳跃。角色持枪姿态与投掷表现先用能看懂的简化动作完成，专门制作动画不作为第一轮原型的前置工作。

5 三类机关

D01 弹射装置，在激活位置下方的可承托地面起柱，弹起柱子作用范围内的角色和可移动道具。

D02 爆炸装置，在被击中的当前位置产生爆炸，造成范围伤害和推力。地面和空中共用同一规则。

D03 发射装置，在命中位置启动，锁定启动弹丸的世界飞行方向，持续发射短时弹丸。装置保持重力与移动，形成移动火线。

以上为建议规则的概括。携带状态、重复命中、墙壁阻挡、过期和数量上限必须按 道具与交互规则 实现。地面与空中的区别来自空间条件，不另开六套技能。

6 敌人与关卡流程

P0 使用一套带明显攻击预警的射击 AI。三种颜色加形状标记的变体分别固定掉落 D01、D02、D03；它们在首版中可以共享移动、瞄准、射击与血量。差异化攻击留在 P1。

完整流程：标题与操作说明 → 分步教学 → 三波战斗 → 胜利或失败 → 重开。每波开始前有短暂准备阶段，玩家可以查看和调整未激活机关。清完存活敌人后进入下一波；胜负转换时立即停止伤害、生成和机关工作，避免结算后继续死亡。

大型场地采用一张连续竞技场，按三片交互区域组织。灰盒尺寸及敌人数量见 关卡、界面与资源规格。验证房是制作工具，不替代正式大型场地的已确认意图。

降范围时保留三种机关、投掷空中激活与真实连锁；优先减少美术、额外敌人行为和波次扩展。否则核心创意会退化为普通波次射击。

8 早期验证与设计冻结

G0 从现有模板工程确认环境能编译并打包，工程创建子项已完成。G1 验证投掷、空中射击与方向理解。G2 验证同一规则在不同布局中产生连锁。G3 验证三波闭环。G4 核查提交包与审核状态。

G2 通过后冻结道具类型、状态与接口；参数仍可调整。修改规则时，先在 设计决策 记录原因、影响的规则 ID 和测试 ID，再更新权威文档及实现。冻结指减少变化，并不要求为常规修改向用户重复请求批准。

原型失败时先定位相机、判定、反馈或规则问题；当 G1 尚未成立时，不进入完整场景美术制作。文档不能保证完全免返工，但能把不确定性集中在前期验证。

9 成功标准与交付事实

设计目标：第一次试玩能理解三种道具；能够完成一次有意安排的空中激活；看到并尝试复现至少一种连锁；可以从标题进入战斗并完成胜负重开。

这些是待验证目标。目前已核对模板工程文件存在，尚未验证本作自定义玩法、试玩或性能结果。开发任务、验收方法和证据格式分别见 开发任务与排期 与 测试计划与验收。

3 命中上下文

每次命中至少携带 SourceActor、InstigatorPawn、ImpactPoint、ShotDirection、Damage、HitId，与 技术设计 的 FHitContext 同名。ShotDirection 是命中前弹丸的世界单位速度方向；步枪用实际枪口射线的单位方向。不能用表面法线、玩家之后的朝向或装置旋转替代。飞行弹丸 HitId 沿用其出生时唯一 ID；命中扫描每一枪生成新 ID。

飞行弹丸忽略生成它的发射器或射手自身，其他目标按规则处理。忽略生成者仅避免出生自撞，不给其角色额外的爆炸免伤。敌人和机关共用弹丸处理路径。

命中 Dormant 时，先以幂等检查锁定 Active，再执行效果。命中 Active 时只消耗弹丸，装置不重置寿命、不更改方向。角色受伤与道具激活是分别处理的目标类型，不能把道具当作血量归零后才启动。

4 弹射装置 D01

流程：命中锁定 Active → 沿世界负 Z 探测 → 验证承托表面及整个最终柱体空间 → 生成柱子 → 扫描伸出过程中覆盖的角色/道具 → 对每个目标施加一次向上速度 → 停留与收回 → 清理。

承托表面必须位于探测距离内，表面向上法线满足配置阈值，并被关卡标为可起柱。高台顶面可以标记为可承托表面；纯装饰、动态道具和其他柱子不作为地面。探测失败时消耗道具并播放明显的失效反馈，不在无限深处或天空生成柱子。

柱子落点按激活时的位置固定。最终柱体体积被不可移动几何或天花板阻挡时采用同样失效处理；移动角色在柱子作用范围内属于正常弹射对象。生成柱子后，来源种子关闭本体可见、碰撞与物理，保留逻辑 Active 和同一名额直到柱子结束，不作为净空检查的占用物。

角色使用运动组件的速度处理，可移动道具使用物理速度处理。弹射保留水平速度，把竖直速度设置为 玩法参数基线 对应的目标值，柱子不直接造成伤害。P0 无坠落伤害，场地外安全处理见第 9 节。每个目标在本次柱子工作期间最多弹射一次，包括后来移动到柱体伸出区域的目标；伸出结束后不再新增弹射。

柱子升起阶段关闭实体阻挡，以查询体积执行弹射，避免主动弹射与物理挤压叠加。完全伸出后，在停留阶段检查柱体体积是否已无角色及物理道具；净空才启用实体支撑与弹道阻挡，未净空就等待至停留结束，不强行夹住目标。收回前先关闭实体碰撞。矩阵中的柱子阻挡只在该实体阶段生效。

5 爆炸装置 D02

流程：命中锁定 Active → 固定爆心 → 对半径内去重后的角色结算一次伤害 → 对有无遮挡作用路径的目标施加推力 → Spent → 效果结束销毁。

建议初版范围内固定伤害；距离衰减延期。伤害与推力都受静态实体掩体遮挡，以爆心到目标代表点的静态遮挡查询为准。同一角色的多个碰撞组件不能导致多次伤害。

水平推力沿爆心到目标的水平径向，附加向上速度；若水平距离为零，采用激活弹丸方向的水平投影，仍为零时采用固定世界前向。推力有速度上限，以免叠加把对象送出场地。

Dormant 道具和 Active D03 接受推力，Held 道具不单独运动，柱子固定不被移动。角色持有道具时仍承受爆炸伤害和推力。爆炸不调用其他道具的激活接口。

同一帧多个外部推力先按目标合并全部爆炸速度增量，再应用本帧柱子的目标 Z 速度，最后按 Gameplay_Parameters.json.limits.maxExternalVelocityCmPerSec 限制速度大小。角色和可移动道具使用同一处理顺序，避免回调次序改变结果。

6 发射装置 D03

流程：锁定 Active 与 Direction → 发射方向可见提示 → 等待短启动延迟 → 按固定间隔生成 P01 → 到期停止计时 → Spent → 清理。

方向固定在世界空间。装置受重力、碰撞和推力影响，弹丸出生点跟随装置位置移动；外观发射口或方向标记必须与固定方向一致，不能展示为朝另一侧发射。

启动后第一发与后续发射时刻由 玩法参数基线 规定。到期时先停止计时，严格小于有效期的发射时刻才可生成弹丸。出生点被世界静态几何阻挡时消耗该发，不在墙内生成弹丸；不因此延长工作时间。

8 数量与计时边界

计数范围：Dormant、Held、Active 种子或装置各算一件道具；D01 从种子到柱子的转换沿用同一名额，不重复计入。Spent 立即移出计数，残留视觉效果不再参与玩法。已经飞出的弹丸独立采用寿命及弹丸上限。

总道具满额且有新掉落时，清理最早生成的 Dormant 再生成新道具；没有 Dormant 时不生成本次掉落，并给出短提示。Held 和 Active 不被该策略抢占。直接生成新物件前检查容量，不能先超额再等待下帧清理。

同类 Active 柱子或发射器满额时，启动新装置前结束最早启动的同类装置，再开始新的。关闭发射器计时器；柱子先释放 Active 名额并关闭实体碰撞，进入收回流程且不再弹射。无法安全释放名额时拒绝新启动，保持 Dormant 并提示，命中弹丸仍消耗。此为安全策略，正常三波应很少触及，测试必须覆盖。

飞行弹丸达到上限时，本次生成失败并消耗该发，不延长发射器有效期或追加补发；敌人的射击也共用该限制。P01 为直线低速弹丸，重力系数为零；这是弹丸的规则，D03 机身仍保持重力。

Dormant 累计闲置计时在 Held 时暂停、恢复时继续；Active 使用自身工作寿命。玩家死亡时 Held 道具随本局清理，不额外生成死亡掉落。暂停时所有玩法计时、物理和弹丸均停止，界面输入仍可工作。

9 关卡边界与重开

目标对象离开关卡安全体积时：玩家判负进入重开界面；敌人只注销一次并结算该波计数，不生成界外掉落；道具和弹丸清理并释放名额。以安全体积保证活着的敌人不能永久卡在地图外。

重开复位血量、弹药、输入持有锁、波次、所有临时对象、计时器、道具计数和掉落结算记录。推荐重新加载本关作为 P0 重开方式。开始新波不等于重开：有效的未激活道具按剩余寿命保留，过期规则仍生效。清波必须同时满足存活敌人数为零和待生成敌人数为零，不能在两批之间提前进入下一波。

建议色形共同编码：D01 青色＋向上三角棱柱；D02 橙色＋球体/爆炸环；D03 紫色＋长方枪管/方向箭头。敌人背包沿用对应形状，UI 同时显示 D01/D02/D03 图标。Dormant 常亮轮廓、Active 脉冲/运动、Spent 暗下并消失；色彩不能成为唯一状态证据。敌人起手闪光、低速弹丸轨迹和危险范围应优先于装饰特效。

阻挡命中即消耗 P01，无论接口返回 true 或 false。 墙体、Active D03 和已经启用实体碰撞的柱子阻挡弹丸；Held 本身关闭碰撞，弹丸可继续命中玩家。接口拒绝激活不返还弹丸，也不返还步枪弹药。爆炸和普通物理碰撞不调用 Ballistic 接口。

玩法参数基线 是设计数值权威，运行时从 DataAsset/默认配置读取；本版不承诺自动导入 JSON。首次录入与每次调参都核对 玩法参数基线，禁止在 Tick、关卡脚本或特效里藏伤害数值。

3. 越肩射击与输入

W01：①从相机沿准星射线找第一阻挡点；无命中则取射程终点。②从枪口向该点再检测，只有第二段实际命中才造成伤害/启动机关，ShotDirection 使用第二段方向。两段忽略玩家、枪及 Held 道具。先检测角色胸前到枪口的短段，枪口已被墙体阻挡或嵌入时取消射击伤害，提示“枪口受阻”，避免镜头看到目标却从墙另一侧开枪。SpringArm 防碰撞负责镜头，不能代替枪口检测。Epic：单次射线返回首个阻挡命中

复用已有 /Game/Input 的 IMC_Default、IMC_MouseLook 与 IA_Move/Look/MouseLook/Jump，在现有控制器与角色输入绑定上扩展。新增 IMC_MothGameplay 只映射 IA_Primary/Interact/Aim/Reload/Sprint，不重复建立第二套移动与跳跃输入；新增输入资产放 /Game/MothEffect/Player/Input。IA_Primary 用简单 Boolean，不叠加 Hold/Release 触发器：Started 时若 Held，尝试投掷，并锁定本次按键为投掷；否则开枪。持续 Triggered 仅在本次为射击且满足间隔时开火。Completed 或 Canceled 停止连射并解除该次锁定；投掷后还需满足 throw.minGunRecoverySeconds，松键和恢复计时两项均完成才允许下一次 Started 开枪，失败投掷也须重新按键。暂停、失焦、死亡清除射击定时器，恢复游戏时若鼠标仍按住，先等待松开。这样一记投掷不会同帧把道具射爆。Epic：Enhanced Input 事件

E 在空手时拾取准星附近的最近合格 Dormant，道具到角色需无遮挡；Held 时安全放下，Held 时 R 换弹不生效。拾取关物理、关碰撞并附着手部挂点；投掷先从角色外侧到释放点做与道具体积一致的 Sweep，再检查终点重叠，不能把释放点直接放到摄像机位置。路径阻挡或终点不合法则保持 Held 并提示。Detach 后切回 Dormant、开启重力与物理，设置 玩法参数基线 的初速度；可对物理根启用 CCD 并验证薄墙。放下同样检查空位，反复拾取放下不刷新累计闲置寿命。

4. 物理与三种机关

机关用一个 USphereComponent 作物理和射击判定根，视觉挂件不另模拟物理或接收命中。Dormant/投掷/Active 发射器由 Chaos 物理移动，重力始终开启；不同时用 ProjectileMovement 移动机关。P01 则用 Sphere 根 + ProjectileMovement，不启用根的 Simulate Physics，以 Sweep 检测命中，按 玩法参数基线 设置 gravityScale=0，保持直线飞行。Epic：ProjectileMovement 与物理模拟关系

角色保持 CharacterMovement，不给胶囊开启物理。ReceiveImpulse 在角色/机关实现内缓存事件，按逻辑帧统一结算：当前速度加本帧全部爆炸增量 → 如有柱子事件，将 Z 替换为角色/道具的 launcher 对应目标速度 → 对角色和机关都按 玩法参数基线 统一上限 Clamp。同帧多柱目标相同，不重复叠加；回调先后不影响结果。结算得到最终速度后，角色只调用一次 LaunchCharacter(FinalVelocity, true, true)；物理机关只对根调用一次 AddImpulse(FinalVelocity-CurrentVelocity, NAME_None, true)。角色 Launch 在下一移动 Tick 生效，不能在每个命中回调里分别 Launch 覆盖待处理速度。没有柱子时保留爆炸叠加结果；没有爆炸时柱子保留原 XY 并替换 Z。Epic：LaunchCharacter；Epic：Add Impulse

  • D01：从激活位置沿世界 -Z 做 JamGroundTrace，只允许 WorldStatic，并校验关卡可承托标签与向上法线阈值，忽略 Pawn、道具和生成柱子。再检查整个最终柱体体积的静态空间，底部承托接触不算障碍；遇天花板、墙体或无合格表面都消耗种子并反馈失效。成功后种子关物理/碰撞/可见，保留逻辑 Active 到柱子结束，共用一个计数名额。柱子固定在落点，拆成视觉、上升查询、实体 Collider 三个组件：伸出时实体碰撞关闭，按上升路径检测 Pawn/JamDevice，AffectedActors 按 Actor 去重，每个对象弹一次。完全伸出后，在停留阶段检查完整实体体积，无角色/可移动道具占据才开启 WorldDynamic 的支撑/阻挡；有占据则等待净空，不强行开启挤压对象。停留结束前未净空则本次不启用实体。收回或被容量策略提前结束时先关实体碰撞、停弹射，再缓降网格。支撑尚未就绪时用较淡外观提示；启用后变实色，避免玩家误判可站立时机。
  • D02：激活时冻结世界爆心，用一次球形查询收集角色/可移动机关，按 Actor 去重；遮挡规则遵守 道具与交互规则。伤害只给 Health，推力只给 ImpulseReceiver，两条路径不能顺便触发机关。
  • D03：激活保存 LockedDirection = Context.ShotDirection，定时器使用当前装置位置和固定世界方向生成 P01；机身旋转、掉落、推力都不改方向。首发延迟、间隔和总时长来自 玩法参数基线；到期清 Timer、置 Spent。弹丸忽略生成它的 Actor，除此不按阵营过滤；出生点到出口先检测，出口被墙挡住就消耗该发，不在墙后生成。方向箭头按锁定方向绘制。

6. 生命周期与验证

死亡先设置 bDeathProcessed，停 AI/射击，再请求一次掉落并注销存活敌人。掉落 Spawn/登记失败也不能再次掉落；容量淘汰顺序遵守 道具与交互规则。Held/Active 仍计入场上机关数；Spent 进入时立即取消玩法 Timer、关闭碰撞并注销，短效果后 Destroy/EndPlay 再注销也无副作用。激活前先预占 Active 容量，同类满额先安全结束最老同类并释放名额；不能安全释放则拒绝本次激活、保持 Dormant 并提示，不能执行半个效果。D01 无地面/无生成空间属于已启动后的失效，需走 Spent 清理。

AWaveDirector 分开维护 AliveCount 与 PendingSpawnCount：排定批次时先登记全部待生成数，每个生成任务成功或明确取消时扣 Pending，成功才增加 Alive；敌人死亡或越界注销只扣一次 Alive。仅 AliveCount0 且 PendingSpawnCount0 才清波，不能在两批间无敌人时提前通关。生成间隔、安全距离、预警和重试读 玩法参数基线 的 flow/enemy；失败重试仍计 Pending。重开/结算显式取消未完成任务并归零，不能把暂时失败当作成功清波。

重开首版用重新加载主地图：先冻结生成/攻击，清 Timer、持有引用、弹丸和机关登记，再 OpenLevel；新局从关卡初值恢复。EndPlay 清理所有对象的 Timer/委托，回收弹丸先禁用碰撞并置 bImpactProcessed，再处理接口和 Destroy，阻止重复 Hit 或延迟回调。

编译器、默认地图、Cook 和首个独立包检查见 UE 工程配置，按 G0 执行；当前没有运行通过证据。

实现依次验收：空中投掷/方向锁定 → 连锁/幂等 → 角色与物理道具弹射 → 死亡掉落/容量 → 三波胜负/重开。每一步同时在 PIE 与独立包验证，具体案例见 测试计划与验收。日志记录 HitId、状态前后、方向、登记数和构建版本；开发调试线/日志受 Development 开关控制，提交包关闭。
