## 1. 验收依据与执行方式

2026-10-08 T07 结果：用户增量构建成功，`MothEffect.Devices` Test Run 3 六项 Automation 均 Success；用户明确确认仅 PIE 基础拾取、放下和投掷通过。证据见 [T07 验证日志](Evidence/T07_Verification_2026-10-08.log)，分支状态见 [T07 接入第 6/8 节](../05_Development_Guide/Device_Interaction_Setup.md#6-pie-顺序与记录)。完整 TC02/TC06/TC17/TC36/TC37/TC31/TC38 仍待适用边界记录；以下完整案例不据此改为通过。助手未编译或运行 UE，静态检查不作为玩法证据。

规则唯一依据是 [道具与交互规则](../02_Design_Doc/GDD/Device_Interaction_Rules.md)，实现职责见 [技术设计](../02_Design_Doc/TDD/Technical_Design.md)，AI、三波与场地见 [关卡、界面与资源规格](../02_Design_Doc/GDD/Level_UI_Asset_Specification.md)，数值唯一依据是 [玩法参数基线](../02_Design_Doc/GDD/Gameplay_Parameters.json)。测试里的时长、距离、伤害、速度和数量均从该 JSON 当次基线读取，不在本文件再维护一份数值表。

先在验证房用固定位置、可显示状态/命中方向/伤害的调试对象执行规则测试，再在主竞技场执行流程和压力测试。PIE 可帮助定位问题；G0、G3、G4 的关键结果必须在独立 Windows 包体复现。调试生成、强制状态和计数工具仅供开发测试，最终公开包不得依赖它们才能玩。

每次测试记录构建标识、参数基线版本、环境、步骤、实际结果和证据。状态只用“未执行 / 通过 / 失败 / 阻塞 / 不适用”；不适用必须说明为何已不属于当前范围，不能把核心机关测试标成不适用。

## 2. 提交阻断级别

| 级别 | 定义与例子 | 提交处理 |
|---|---|---|
| S0 致命 | 游戏无法启动、可重复崩溃、包体缺失、无法进入主关卡、无法完成必经流程、审核拒绝且未修复 | 阻断提交；必须解决并重测 |
| S1 重大 | 空中启动、方向锁定、真实连锁等核心规则错误；重复爆炸/持续弹射；重开残留；三波不可完成；容量失控；平台下载后的包不可玩；基准配置严重卡顿影响瞄准 | 阻断提交；不能用说明文字代替修复 |
| S2 一般 | 非核心提示不清、偶发轻微穿插、可绕开的场景问题，核心流程完整且不会误导规则 | 可带已知限制提交；记录复现、影响与取舍。若实际阻挡教程或核心操作，升级 S1 |
| S3 外观 | 装饰缺失、低影响特效瑕疵、非必要动画表现 | 可延期；不为此挤占审核缓冲 |

关键规则测试全部需有结果。未执行的核心规则/本地包测试不等于没有 S1，应当阻断候选包本地放行。TC29 分阶段记录：本地部分在上传前完成，平台自测部分在上传后、提审前完成；两部分都通过才把 TC29 标为通过。全部测试通过也不能代替 [发布检查清单](../07_Release/Release_Checklist.md) 中的平台认证、上传解析、自测与审核。

## 5. 性能基准：机器未定，结果未测

## 6. 证据与缺陷记录

每个关键门槛至少保存一段可重现的短录屏或日志。建议开发项目内用 `QA/<构建标识>/` 存截图、录屏、测试记录和缺陷记录；这些目录是未来项目约定，不是本次已经创建的测试证据。

测试记录最小字段：测试 ID、构建标识、参数版本、执行日期/人、环境、实际步骤、预期、实际结果、状态、证据位置、关联缺陷 ID。缺陷记录最小字段：BUG 编号、S0–S3 级别、可复现步骤、出现频率、影响、关联测试、修复构建、回归状态。字段用于以后真实执行，不预填“通过”。

最低回归范围按影响确定：触发/碰撞/命中上下文变更重测 TC03–TC19、TC33；状态/生命周期/计数变更重测 TC06、TC12、TC18–TC20、TC23、TC27–TC28、TC31–TC33；波次/AI/场地变更重测 TC17、TC20–TC23、TC26–TC29、TC32–TC33；纯参数变更重测相关规则与完整三波。提交候选包至少重测全部核心规则、三波、重开、压力及最终包启动。通过后没有新变更或新问题，不无限重复所有测试。

玩家行动、输入门控、移动/动画或武器任务变更另重测 TC06、TC24、TC31、TC34–TC38 中受影响分支；正式候选包覆盖全部玩家专项用例。纯骨骼/动画表现调整仍须确认不会改变移动、射击或投掷恢复窗口。
